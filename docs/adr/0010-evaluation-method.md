# 0010: Evaluation method: quote-labelled questions, a fixed tuning/test split, and a judge only where code can't decide

- Status: Accepted
- Date: 2026-11-03

## Context

Phase 3 has to turn SMOI Brain's quality into numbers that can be quoted and defended (NFR-09.01 to
NFR-09.05, NFR-09.08). The numbers are only as trustworthy as the questions and the method:

- labels must survive re-chunking, because chunk size is one of the things being tuned;
- anything that can be checked by code should be, because LLM judges are noisy;
- results used to choose settings overstate quality, so the headline needs questions that were
  never used for tuning.

## Decision

**Corpus.** 24 English Wikipedia articles pinned to a revision (`eval/corpus/manifest.json`), in three
groups of deliberately similar documents: European frogs and toads, relational databases and their
internals, and the outer planets and their moons. Each group mixes TXT, DOCX and PDF.

- The files are generated by `eval/corpus/build_corpus.py` and committed, so a run needs no network.
- Wikipedia's PDF export was rejected because it embeds images, whose licences vary and include
  non-free logos. The script writes text-only PDFs and minimal DOCX files instead, so the only licence
  is the text's CC BY-SA 4.0. `eval/corpus/SOURCES.md` gives the attribution, revision and changes for
  every file.

**Question set** (`eval/data/questions_v1.csv`, one spreadsheet the owner reviews):

- Types: `factual`, `multi_document` and `not_answerable`. Tags mark questions that need the right one
  of two similar documents (`disambiguation`) and unanswerable questions close to what the corpus
  covers (`near_miss`).
- Questions are paraphrased, so keyword overlap with the source isn't a free win.
- Only questions with status `approve` count towards reported results. Before review, results are
  labelled DRAFT.

**Relevance labels are quotes, not chunk ids.** Each evidence item is an exact sentence from a document.

- A retrieved chunk is relevant if it contains the quote, after normalising case, accents and punctuation.
- A quote split by a chunk boundary counts for each chunk holding at least half of it.
- The same labels therefore work at every chunk size.
- A quote that isn't found in its document, offline or in the indexed chunks, stops the run rather
  than silently lowering recall.

**Fixed split.** Approved questions are split once into about two-thirds tuning and one-third test,
stratified by group and type (`eval/data/split_v1.json`, committed).

- Settings are tuned only on the tuning set.
- The test set runs once settings are final. Every test run is appended to
  `eval/results/locked_runs.jsonl` with a fingerprint of the settings (providers, models, chunking,
  answer mode and the backend source tree).
- `docs/benchmarks.md` states how often the test set ran, and flags it if settings changed after test
  results were seen.

**Metrics.**

- **Retrieval:** Recall@5 and @10, MRR@10, and an evidence-level nDCG@10 (a chunk only earns gain for
  evidence not already found), for all four modes. Reported overall, per group and per question type.
- **Answers, computed by code:**
  - outcome counts;
  - correct "don't know" rate on unanswerable questions;
  - false "don't know" rate on answerable ones;
  - citation-rejection rate (FR-06.12, NFR-09.04);
  - the share of cited chunks that contain labelled evidence, and the share of answers citing any
    evidence chunk. This catches a fluent answer drawn from the wrong frog species, which a judge
    reading only the cited passage would accept.
- **Faithfulness, judged by an LLM:** the share of answer sentences supported by the passages the
  answer cites. This is the only judged metric, and it is always reported as an estimate.
  - The judge is configurable (`--judge ollama:<model>` or `anthropic:<model>`) and must not be the
    answer model.
  - If both models are from the same family, the report says so.
  - The owner labels a fixed sample of 30 answers by hand, without seeing the judge's verdicts. Every
    judged run re-judges that sample and reports percent agreement and Cohen's kappa next to the score.
- **Latency:** p50 and p95 (nearest rank) per retrieval mode and per answer stage.

**One command.** `make eval` (or `python eval/run_eval.py all`):

1. creates `.env` with random local secrets if it's missing;
2. starts the Compose stack with the reranker;
3. indexes the corpus for a fresh user;
4. runs everything;
5. deletes that user's documents;
6. writes `docs/benchmarks.md`, which is generated entirely by the script.

**CI regression check.** The `eval` workflow indexes the corpus with the real embedding model and
fails if hybrid retrieval on a 20-question subset drops below `eval/thresholds.json`.

- The subset is drawn from the tuning set, never from the test set.
- The threshold comes from a measured run, named in the file.

## Alternatives rejected

- **Chunk ids as labels:** they break on every re-chunk, which would make the chunk-size experiment
  impossible.
- **An LLM-generated question set used without review:** cheap, but nobody would have checked it, and
  generated questions tend to copy the source wording, which flatters keyword search.
- **RAGAS or similar frameworks:** they hide the metric definitions and judge most metrics with an LLM.
  The owner has to be able to explain each number, and most of these can be computed exactly.
- **The LLM judge also scoring citation correctness:** code can check this against the labelled
  evidence, so it does.
- **Wikipedia's PDF export:** rejected over image licences (see above).

## Consequences

- The corpus is small (24 documents, a few hundred chunks) and English-only. Retrieval latency here
  says little about scale; NFR-06.03 measures that in Phase 4.
- The generated PDFs have simple single-column layouts. They test PDF text extraction and page
  breaks, but not multi-column layouts or scanned pages.
- Quote matching treats a chunk holding half of a split quote as relevant even if the half doesn't
  contain the key fact. Quotes are kept to one sentence to limit this.
- With about 25 test questions, differences of a few points between modes are within noise. The
  report gives counts so this can be judged.
- The judge's estimate is only as good as its agreement with the owner's labels, which is shown next
  to it.
